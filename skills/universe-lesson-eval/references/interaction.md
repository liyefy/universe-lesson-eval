# 交互与控制反馈

依据本轮确认的需求、[项目根规则](project-setup.md)、[项目公共索引](project-setup.md) 与适用的用户交互要求。外部 NB宇宙规则没有某节时，不虚构“交互规范”来源。

保留单步反馈简洁、多目标进展可知、操作不空泛重复的既有目标；按来源、版本、适用结构实例化。组件属性是线索，缺陷须证明实际违背预期；严重度统一见 [labels.md](labels.md)。

## INTERACT-01 单步操作与有效进度

- 对单次点击/播放节点，判断反馈是否说明真实状态或有效进展。已确认设计要求单步操作不附加占位进度时，检查按钮、主导航与反馈是否按该要求工作。
- `total=1` 或 `showTrack=false` 不能单独证明“伪进度”；先区分离散任务、连续物理量、播放进度和纯状态。需要连续过程取证的一个任务可以存在有效进度。
- 可用浏览器断言操作前、进行中、完成后的按钮与导航状态；模型只判断仍有歧义的信息价值。
- 证据：该操作的完成条件、组件配置和实页前后状态；不能仅凭属性值登记严重问题。

## INTERACT-02 多目标任务的可见进展

- 本节点包含多个必做操作/采样目标时，学生须能辨认目标、已完成项与剩余要求；以本轮明确设计选用公共清单、计数或进度，不只看是否有轨道。
- 复用适用公共组件；不要为了显示进度新增可跳转的整套探索目录。是否允许点击定位/吸附须服从真实取证要求，不由审查擅自增加。
- 按未完成、部分完成、全部完成做浏览器断言，核对可见目标/计数与真实完成条件；重复触发不能伪增计数。
- `showTrack=false` 且存在清晰有效的其他反馈不自动失败；有轨道却不能辨认任务也不自动通过。
- 证据：目标集合、完成条件、各状态的可见反馈和导航变化。

## INTERACT-03 操作与状态文字的信息量

- 比较按钮、邻近说明、状态与读数的实际用途。检查重复动作且不提供额外信息、无来源的新提示，保留有必要的单位、约束、错误/重试、加载及完成反馈。
- 同一动词重复不必然冗余，无数字不必然无价值；“正在加载”“请先选择对象”等可以提供真实必要信息。也不能用无关数字为冗余提示免责。
- 程序先采集文本/出现状态并定位重复候选；需要模型时提供整段操作上下文，要求说明新增信息、依据及删除后影响。
- 证据：按钮与提示原文、来源/用途、对应状态及实际影响。术语问题归 [CONTENT-02](content.md#content-02-文字来源与必要信息)，避免同一问题重复扣分。

## INTERACT-04 连续操作、容差与中断

- 检查滑块、模型拖拽/拾取、吸附及停留取证。精度和容差来自科学目标、输入方式与本轮明确需求；不能默认所有场景必须为 400–800ms、±2.5% 或 ±2°。
- 判定边界用确定性测试覆盖，公开 UI 验证目标是否可达、反馈是否及时、快速划过是否误记。只有可用的控件才测试对应路径。
- 需要持续可见观察的任务，检查失焦/后台/取消是否停止未完成取证；普通状态保留按需求处理，不要求所有交互失焦都重置。
- 时间目标若未规定，记录实际时延、操作成功/失败和用户影响；证据不足时不凭感觉给出违反阈值的结论。
- 证据：实际参数/条件、边界输入输出、真实操作与计时方法。

## INTERACT-05 练习整轮与完成记录

- 以根规则当前默认整轮逻辑为基线：一题选择后锁定并显示反馈；已作答即能继续，无论对错；答完统一结算，整轮全对才完成，未满分由显式重答清空整轮。
- 文档明确要求逐题掌握型流程时核对已确认偏离依据。旧文中“可重选”的冲突按 [prepare.md](prepare.md) 记录，不能把不可改选本身当缺陷。
- 静态核对答案存在性、整轮评估和持久完成写入；浏览器覆盖错误答案继续、整轮非满分、显式重答与满分结果。
- 证据：选择/导航/结果状态、实际轮次和完成记录边界；不操作未授权真实账户数据。
