# 准备与依据

主代理读取。先确认可核对的来源与范围，再派发任务；不从实现反推产品要求。

## 来源与制作阶段

- 沿用用户给定的专题和地址，从 `src/routes/universeModuleRegistry.ts` 解析实际身份；专题是模块内部状态，不猜专题路由。
- 读取当前适用的 [项目根规则](project-setup.md)、专题需求与已确认修订。外部规则从用户提供的位置或项目本地配置 `rule_documents` 解析；当它引用语言或设计规则且本轮涉及该范围时，读取实际引用文件。
- 未提供专题原文时，冻结当前代码/页面的既有文案底本，继续检查科学性、界面与流程；将“底本一致性”与“符合外部需求”区分。现状不是科学正确性证明，也不能证明自己满足未提供的需求。
- 修正建议基于已证实问题做最小必要调整，保留无争议原文。验收不自动执行修复，不以精简、短句或风格偏好为由改写已确认教学内容。
- 将实际采用的来源快照保存在计划目录内，登记 `sources:[{id,path,sha256}]`。每项规则登记 `id/source/version/applicability`；`source` 引用来源 ID，`version` 标识实际版本，`applicability` 说明适用专题、文本类别、阶段或视图。case 的 `source_ids` 必须包含其规则来源，`source` 保存可读锚点。
- 术语表、句长、延时、容差、比例、边距等规则须有本轮来源和测量口径。外部语言规范中的讲解短句要求只能在其实际适用类别内检查，不能扩为所有 UI 文本超过 18 字即严重缺陷。词表命中和统计告警只是待核对事实。
- 冻结音频阶段：尚未进入最后音频制作阶段时，声音、实播同步和依赖真实 `natural-ended` 的时序项允许 `not_applicable`，写明阶段依据。不要求临时补 cue、manifest 或音频，也不运行缺失音频检查制造问题。
- 已启用音频、本轮明确验音，或最终交付范围已约定旁白时，相关声音项必须检查；已有错误或过期音频不能以后置阶段豁免。动画、文案与动作映射及无音频时应成立的交互继续检查。

## 冲突必须落到实际依据

建立短表：`冲突条款｜来源版本与锚点｜采用依据或未决点｜理由｜受影响 case`。

按本轮用户明确指令、当前适用的 AGENTS 和已确认需求处理。既有技能、组件示例、历史记录不能自称“已统一”而免于核对。能由当前权威明确裁决的直接记录，不重复请求批准；关键分歧无法求证时，仅相关项记未验证并继续独立部分。

常见核对点：

- 假设卡以当前完整论证节点、全部必要操作和 cue 为门槛，不按旧版固定阶段名称裁决。
- 根规则的练习默认整轮锁定，题目已作答即可继续；若旧语言规范要求错误项“可重选”，记录来源冲突及本轮采用依据，不能只按旧文或旧技能自动判错。
- 外部画布/相机要求与既有共享避让机制须结合当前实际规则和调用链判断；“已复用公共组件”不是行为合规证明。
- 满铺主舞台、单层段落气泡、跨阶段素材一致是已有验收目标，按其具体视图与当前来源登记；不把主舞台要求套到明确设计的画中画，也不把同一观察视图的素材规则扩为禁止所有示意图。

规则争议、环境错误与产品缺陷分开。不得倒改需求迁就实现、删除失败 case 或挑旧版宽松规则。

## 环境与版本

记录来源版本/哈希、代码提交及工作区差异指纹、页面实际 `build_id`、浏览器、CSS 视口、DPR、输入方式和模拟/真机属性。不能给未核对的页面随意填当前提交号。

黑箱 URL 冻结最终落地且去凭据的完整地址，保留模块路由；跨页 case 可覆盖 URL。不可达时记录实际尝试的地址，相关项未验证；地址或构建不符须修订计划重跑，不能据此判产品缺陷。使用本地或已授权测试环境，不清空真实用户数据。

报告目录为 `.local/universe-evals/<任务ID>/`。按 AGENTS 登记范围、检查重叠与忽略规则；各执行者写独占证据目录，主代理维护同一 RCL。

## 冻结节点和检查路由

1. 从来源盘点阶段、节点、假设及客观正误、操作要求、关键动作、题目反馈；已接音频时加入实际 cue。错误假设和干扰项按教学角色保留。
2. 在 `inventory` 登记每节点的 `required_rules`。full 的课程来源同时保存从原始内容提取的 `node_ids`，与 inventory 逐项对应；每个节点声明 VIEW-01/02/03 的适用性或有依据的 N/A。全景、画中画、科学终态分别判断，不能只在某个探索节点查一次就代表提问和结论均已验。
3. 为每项写原文锚点、可观察预期、适用性和前置条件。默认 `coverage:full` 声明 science、interaction、motion、viewport、hypothesis 五维；明确局部任务用 `focused` 和对应子集。按 [schema-v2.md](schema-v2.md) 冻结 `visual_states` 与 `scope.viewports`，面板开关、必要科学终态及过渡不能藏在标题里；其它领域仍可用 `required_variants` 约束。没有终态或过渡的节点写冻结依据，不人为创造动作。
4. 先找确定性判据：静态事实用 `engine:static`；公开 UI 可自动断言的行为用 `browser`；只有语义或感知仍需裁决时才用 `model` 并写 `model_reason`。同一命题只分配一个主要维度，避免交叉章节重复扣分。
5. 按 [工具契约](automation.md) 指定证据通道。含 blackbox 的 case 冻结实际状态、步骤、CSS 视口和观察方法；需要听音的与纯 DOM 门禁分开。没有来源的时差或容差阈值不自行补造。
6. 用机器覆盖检查发现漏项；原始清单存在歧义或复杂论证时再做聚焦独立审阅。冻结后变更来源、范围、构建或预期，须新计划版本重新冻结并重取相关证据，不能事后改 lock 适配结果。

冻结与任务包的具体命令见 [automation.md](automation.md)。内容快照用于追溯，不意味着来源或执行者身份已经由哈希证明。
