# 聚焦任务与独立复核

主代理读取。按工作量和判断风险分工，不因有五个维度就创建五个代理。

## 先确定性执行，再分发判断

- 主代理可直接完成来源盘点、脚本运行与小规模浏览器断言。适合拆分时，将同一领域的一组相关节点交给一个执行者，避免每条断言都新建代理。
- 并发上限按实际槽位和资源设置，通常从 1–2 个小包开始；完成后收回结果再派下一波。工具/环境不足影响对应 case，不需要编造代理或模型。
- 确定性通过项由实际断言闭合，不再重复模型检查。模型只处理已写明 `model_reason` 的语义、教学逻辑、视觉或听觉判断。
- 任务包生成、结果分片与覆盖合并使用 [automation.md](automation.md) 的工具；主代理处理漏项/重复/冲突，不能用人工汇总把缺口消掉。

| 工作 | 必要输入 | 交付 |
| --- | --- | --- |
| 来源盘点 | 相关原文、规则版本、范围 | 节点、规则适用性、未决冲突 |
| 确定性检查 | 分配 case、静态入口或公开 UI 路径 | 命令/断言记录与所需页面证据 |
| 模型语义 | 问题相关原文及必要前后文、判据 | 论证、引用、结论与不确定性 |
| 模型感知 | 原文/预期、实际环境或原始媒体、公开路径 | 所见/所听、时点、结论与边界 |
| 缺陷复核 | 中性任务、相关来源、必要原始材料 | 独立观察或新重跑，确认/不确认与证据 |
| 写表 | 已合并且复核通过的问题、授权范围 | 串行登记与回读；只在需要时启用 |

## 小任务包

```text
目标：专题、节点段、规则 ID 与本包 case ID。
计划：只读路径、哈希、实际 build_id；本次 RCL ID。
依据：相关来源片段、版本/锚点、适用性、已裁决冲突。
预期：可观察或可计算的命题；必要前后文与前置条件。
执行：engine、允许工具；页面地址/视口/输入方式或命令入口。
输出：独占结果与证据目录；每个 case 都须给状态和理由。
边界：不修改产品/需求、不写远端；缺证据标未验证。
```

一次任务应是一个连贯目标，可以包含该目标所需的多条断言。纯提取或计算交给代码；模型任务允许“成立/不成立/证据不足”及理由，不强迫是非回答，也不在问题中预埋“违规”“敷衍”等结论。

例如检查某项假设是否完成论证时，提供假设原文、相关完整教学段落及操作要求，要求指出支持/反驳链、仍缺条件和完成节点；不能只给最后一句，让模型替遗漏的前置论据背书。术语检查提供课程对象、年龄段与实际来源，不因词典未收录就暗示其错误。

## 保持独立而不丢上下文

- 初审任务不携带完整会话、前次评分、候选缺陷或拟修复方案。使用无历史继承的代理会话；必要的课程上下文通过任务包显式提供。
- 黑箱执行者不读实现源码、私有 Store 或隐藏调试接口来判用户效果；定位原因交给代码任务。来源分析可读代码底本，但须与真正黑箱观察分清。
- 独立复核者先执行中性任务形成自己的观察，再比较候选结论。语义判断的必要上下文不能因“闭卷”被删掉。
- 确定性问题可由同一执行者独立重跑，须新的运行和产物；含模型判断的问题由不同于初审结果/证据执行者的复核者处理。具体证据门槛见 [labels.md](labels.md)。
- 记录真实代理/执行者标识及可知的模型；同一模型可有独立执行者，同一执行者换角色或换名字不等于独立。用户明确要求不同模型时才额外按该要求安排。

## 共享资源与合并

- 同源标签页通常共享存储，不能当独立测试身份。确需并行浏览器时使用可确认隔离的 context/测试会话；否则串行操作。
- 相机、学习进度、账号或浏览器控制共享时，由单一执行者操作；其他代理可并行分析已保存证据，不抢同一页面。
- 子代理只写自己的结果和证据；主代理维护 RCL、冻结计划和最终合并。复核材料用新目录，保留初审证据。
- 若无法满足模型问题的独立复核，保留候选为未验证，完成其他检查；不以降级名义输出已确认缺陷。没有复核需求的确定性通过项不因此被阻断。
