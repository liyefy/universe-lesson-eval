# 确定性检查先行

读取本文件、[automation.md](automation.md) 和当前领域规则。先把要求拆成可执行命题，再选择静态或浏览器断言。

| 命题 | 优先检查方式 | 证明边界 |
| --- | --- | --- |
| 文案、ID、集合、必填配置 | 精确对照、解析实际导出数据、已有测试 | 从同一配置抄两份相等不能证明实页一致 |
| 假设/练习门禁 | 对已知输入及边界的逻辑断言、真实 UI 路径 | 分支存在不证明播放或点击后实际生效 |
| 可见文字、按钮、任务计数 | 公开页面采集和自动断言 | DOM 状态不证明科学含义、实际听音 |
| 布局边界、遮挡候选 | 页面盒模型、命中测试、截图 | 容器大小不证明模型投影完整或视觉协调 |
| 组件与科学能力复用 | 实际 import、参数与调用链 | 同名或共享模型不证明交互生命周期复用 |
| 音频来源 | 已进入音频阶段时运行现有只读检查 | manifest 可信不证明发音、可听或音画一致 |
| 静态质量 | 范围内 ESLint、已有行为测试、适用 lint:reuse | 检查成功不证明课程可完成 |
| 覆盖与证据绑定 | 计划/结果合并和 gate | 哈希/文件存在不证明观察真实或规则完整 |

`rg`、正则、词表和组件 props 可定位候选，不能自动给出语义缺陷或严重度。例如 `total=1`、`showTrack=false`、长句或陌生术语均需核对实际语义和适用规则；有明确来源的结构约束才可以写成确定性断言。

无现成检查时可在任务证据目录编写最小只读检查，避免新增产品能力或测试依赖。修改仓库持久测试仍遵守当前 AGENTS 与用户授权。存在无法确认的命题就拆出未验证或 model case，不把“源码看起来合理”当效果证明。

## 运行与版本

- 执行 Node 命令前读取项目 `package.json#engines` 并核对实际版本；NB宇宙当前要求 20.x，以项目当前规则为准。先读脚本定义和命令帮助，不猜脚本/参数。
- 用 `run_check.py` 保存实际 argv、目录、输入指纹、退出码、耗时和输出，再按 v2 证据契约封装。非零、超时、未启动分别记录，启动失败/超时不直接判产品缺陷。
- 只运行范围内只读核对；不加 `--fix`，不执行付费 TTS、发布、资源优化或无关安装。
- 需要构建时记录真实命令；`pnpm exec vite build` 不等于完成 `pnpm run build` 的前置检查。全仓既有失败与本次命题分开记录，不删除失败证据，也不阻止可独立进行的页面检查。
- 代码与实际页面须对应同一 build_id；未提交工作区保存差异指纹。旧页面、旧构建证据不能由当前源码补签。
- 凭据不得进入命令、快照、日志或地址。证据工具不替执行者证明真实性；检查断言是否真的覆盖预期。

确定性缺陷先以全新运行确认，不强迫附加模型裁决；语义缺陷按 [labels.md](labels.md) 独立复核。具体 CLI 见 [automation.md](automation.md)。

## 按需使用相关技能

- 审查 R3F/Three.js/Drei/Zustand 实现时读 `r3f-best-practices`（定位见 [项目接入](project-setup.md)） 及相应规则。
- 跨设备/安全区读 `universe-responsive-ui`（定位见 [项目接入](project-setup.md)） 的验收部分。
- 已进入音频阶段的 catalog/manifest 检查读 `universe-lesson-tts`（定位见 [项目接入](project-setup.md)），不继承生成授权。
- 只使用本次需要的检查能力，不因相关技能包含修复步骤就修改产品。
