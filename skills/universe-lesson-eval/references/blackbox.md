# 真实页面黑箱

以学生实际可见、可听、可操作的界面为对象。黑箱是一种证据边界，不等同于必须使用模型。

## 自动断言与感知观察

- 使用当前允许的浏览器工具、自动化或人工式 UI 操作，遵守该工具的访问限制。通过公开 UI 进入状态后，读取可见 DOM、可访问性树、控件边界和反馈并做确定性断言，可用 `engine:browser`。
- 浏览器 case 同时提交 `code` 执行记录和 `blackbox` 页面证据。实际所处状态、CSS 视口、来源 URL 和 build_id 必须与计划一致。
- 科学画面的含义、视觉协调、动作连贯性或声音理解不能由现有断言覆盖时，另列 model case 并说明原因，不让模型重复已充分验证的计数和按钮状态。
- 不读私有 Store、内部函数或隐藏调试对象替代用户效果；不注入状态、调用完成回调或跳过交互门槛。网络/控制台只作为故障旁证，不以成功响应替代可见效果。
- 截图用于视觉判断时必须实际查看。单张终态图不能证明过程、顺序或平滑；动态命题须有真实执行序列、测量或足够的录屏/关键帧。
- 听觉项必须实际听到相应片段；音画项同时观察画面，记录原句、时点及变化。字幕、媒体时钟、时长、事件日志不能单独证明可听性、发音或音画语义一致。
- 音频后置且本轮尚未接入时按冻结依据记声音/实播同步为 N/A；动画单独验收。已要求验音而不能听时记未验证。页面不可达、错误环境或状态无法进入先记录边界，不自动归因产品故障。

## 一次 case 的执行

1. 核对实际版本、环境、视口/DPR、输入方式及初始学习状态。
2. 按公开路径进入冻结状态，观察前态，执行操作。
3. 对照明确预期，保存实际断言、观察、时间及原始证据；不以“看起来正常”代替结果。
4. 候选确定性问题按相同前提新建运行重试，保存新证据；间歇问题记录次数和条件，不挑一次成功冒充稳定通过。
5. 如 case 涉及生命周期，检查离开节点后旧音频、动画、提示或完成事件是否影响后续节点。

## 按能力展开状态

以下用于生成计划，不强迫每个静态节点检查全部路径；一旦冻结为 case，不得再靠抽样省略。

| 适用能力 | 需要考虑的状态 |
| --- | --- |
| 必做交互 | 未操作、部分完成、达到条件、返回后的保留/失效 |
| 朗读与演示 | 开始、关键过程、自然结束、暂停继续、重播、快速切步；声音按阶段适用 |
| 已有进度能力 | 变速、拖动进度、断点恢复、跟着学/自由学切换 |
| 假设反馈 | 被选/未选、跨节点论证、多项同证、返回、重播、重新学习 |
| 视口与输入 | 侧栏开关、约定尺寸、旋转缩放、滚动、主按钮与拖拽 |
| 资源错误 | 可在授权测试环境安全复现的加载失败、恢复和重试 |

不存在的产品能力写明来源，不为测试临时新增能力。无法安全复现的必查异常路径记未验证，不清空真实用户数据；不要用整页刷新掩盖切步旧回调。证据封装和复核要求见 [automation.md](automation.md)、[labels.md](labels.md)。
