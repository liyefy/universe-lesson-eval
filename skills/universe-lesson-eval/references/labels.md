# 结果、复核与评分

所有执行者采用同一标注；JSON 与命令以 [automation.md](automation.md) 为准。以下评分只用于 v2。

| 状态 | 含义 |
| --- | --- |
| `pass` | 冻结预期在记录条件下成立，实际完成所需检查且证据齐全 |
| `fail` | 违背明确适用预期，证据齐全，已完成本节规定的缺陷复核并关联一个 issue |
| `unverified` | 未执行、缺环境/听觉/证据、来源争议，或候选问题尚未确认 |
| `not_applicable` | 冻结计划已允许且有具体阶段/能力依据；不参与扣分 |

不使用“继承通过”。未运行不是不适用，实现遗漏也不能反过来豁免需求。音频后置且本轮尚未接入是有依据的阶段性 N/A，其他适用检查继续。

## 检查与证据

- `static` 需要 `code`；`browser` 需要 `code + blackbox`；`model` 需要 `model_reason`，以 `analysis` 和/或 `blackbox` 支撑，不能只交源码命中。
- 每份证据绑定 case、冻结计划哈希、build_id、真实执行者、带时区的采集时间和文件哈希；采集时间不得早于冻结时间。文件位于报告根目录内。
- blackbox 记录实际 URL、状态、视口、步骤和观察方法，必须匹配冻结条件。程序断言、视觉判断、听觉判断分别说明证明范围。
- 哈希和完整元数据只验证绑定与一致性，不证明执行真实、科学正确或身份独立。截图用于视觉判断时须实际查看；听觉判断必须真实收听。

## 候选问题如何确认

| 问题类型 | 可用复核 | 要求 |
| --- | --- | --- |
| 全部关联 case 均为确定性 static/browser | `rerun` 或 `independent` | 重跑允许同一执行者，但须从约定前态重新执行、取得新记录和新产物，不能复用初审路径充当复核 |
| 任一关联 case 为 model | `independent` | 复核者不同于初审结果及证据执行者，独立核对相关来源、实际效果和影响 |

复核证据必须覆盖问题的全部关联 case 和各自所需通道。确定性浏览器问题重跑真实 UI；纯静态问题不强迫再做浏览器或模型复查。模型语义问题独立分析原始材料，视觉/听觉问题独立观察相应效果；不以改代理名字或转述前次结论代替复核。

先提供中性任务、依据和必要上下文，让复核者形成观察，再对照候选结论。复核不一致时补最小证据或保留未验证，不投票或平均意见。已闭合的确定性通过项无需重复模型审查；对模型通过项，仅在后果重大、来源有歧义或证据薄弱时增加独立检查。

## 按独立问题计分

每个 fail 恰好引用一个 `issue_id`。issue 的 `case_ids` 必须完整对应这些失败结果，且维度与 case 一致；`fingerprint` 全局唯一。同一问题在多个节点、状态或设备重现，保留所有 case 证据，只扣一次分。不同原因或不同影响的独立问题不能为减分而合并。

计划阶段先消除跨维度重复命题；若执行后发现归属错误，修订计划并重新冻结受影响范围，不能事后搬维度或拆分同一缺陷获取不同分数。

| severity | 固定扣分 | 依据实际影响判断 |
| --- | ---: | --- |
| `severe` | 20 | 核心科学认知被误导、必做学习链路不可完成、伪造完成等严重影响 |
| `moderate` | 7 | 局部功能、反馈或呈现错误，明确影响学习但未破坏核心链路 |
| `minor` | 2 | 范围有限的细节偏差，对理解或操作影响较小 |

词表命中、组件 props、静态画面或“风格不同”不能自动决定严重度。先证明适用规则和实际影响，再分级；纯偏好和未确认建议不扣分。不使用浮动扣分区间。

## 机器评分

| 维度 | budget |
| --- | ---: |
| `science` 科学与文案 | 30 |
| `interaction` 交互与引导 | 25 |
| `motion` 动画媒体 | 20 |
| `viewport` 视口与排版 | 15 |
| `hypothesis` 假设闭环 | 10 |

由 gate 计算，不在报告输入中手填总分、等级或维度得分：

1. 各维度按独立 issue 累加固定扣分，实际扣分不超过该维度预算；同时保留原始扣分与封顶后扣分，不隐藏超出预算的问题。
2. 声明维度中存在非 N/A case 的维度为活跃维度；全部 case 均 N/A 的维度排除。总分按活跃维度预算归一到 100：`100 × 活跃维度所得分之和 / 活跃维度预算之和`。局部 N/A 不稀释同维度缺陷。
3. 无适用项时 `score.value=null`、`grade=null`。适用项全部未验证、没有任何 pass/fail 时，分数与等级同样为 null，`provisional=true`；有部分已验但仍有未验证项时可给暂定分，`grade=null`。未验证不伪装为零缺陷的正式高分。
4. 全部适用项已核对时，A ≥ 90，B ≥ 80，C ≥ 70，其余 D。等级只描述已冻结范围，不代表可以发布。
5. 所有 severe issue 均进入 `hard_findings`，不受总分或维度封顶掩盖。没有 severe 只表述为“已确认严重问题 0 项”，存在未验证时不能宣称无硬伤。

v2 输出分开呈现 `valid`、`complete`、`coverage`、`score` 和 `hard_findings`，不提供 `accepted`。退出码：0 为有效且完整（可以含已确认缺陷），1 为有效但有未验证，2 为输入或证据无效。focused 分数须标明局部范围，不能与全课认证等同。v1 保留旧门禁语义，明确标为 legacy，不套用 v2 结论。
